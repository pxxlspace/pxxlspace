`pxxl sandbox` (or `pxxl sandboxes`) manages [sandboxes](/sandboxes/overview) from your terminal. Sign in first with `pxxl login --api-key <key>`, using a key scoped to `all` or `sandbox`.

Wherever a command takes `<sandbox>`, pass its id or its name. Add `--team <id>` for a team's sandboxes and `--json` for the raw API response.

## Create

```bash
pxxl sandbox create --name demo --template node --size small --wait
```

| Flag | What it does |
| --- | --- |
| `--name <name>` | Name. Generated when left out. |
| `--template <id>` | `base` (default), `node`, `python`, `html`, or `php`. |
| `--size <size>` | `micro`, `small`, `medium`, or `large`. |
| `--cpus <n>`, `--memory <mb>` | Custom size instead of `--size`. |
| `--disk <gb>` | `2`, `5`, or `10` (default). |
| `--auto-stop <minutes>` | Pause after this many idle minutes. `0` means never. Default 60. |
| `--env KEY=VALUE` | Environment variable. Repeat for more. |
| `--repo owner/repo` | Clone a GitHub repository into `/workspace`. |
| `--wait` | Wait until the sandbox is running. |

## Run commands

```bash
pxxl sandbox exec demo -- npm install
pxxl sandbox exec demo --workdir /workspace/app --timeout 300 -- npm test
pxxl sandbox exec demo -- 'cd app && npm run build'
```

Everything after `--` is the command. Output streams as it's produced, and `pxxl` exits with the command's exit code (`124` if it timed out), so it works in scripts and CI:

```bash
pxxl sandbox exec demo -- npm test || echo "tests failed"
```

Several words after `--` are joined with spaces and run by the sandbox's shell. Quote the command to keep `&&`, `|`, or `$VARS` away from your local shell.

## Files

```bash
pxxl sandbox files demo                      # /workspace
pxxl sandbox files demo /workspace/src
pxxl sandbox read demo /workspace/package.json
pxxl sandbox write demo /workspace/.env.local --file .env.local
echo "hello" | pxxl sandbox write demo /workspace/hello.txt
pxxl sandbox write demo /workspace/note.txt --content "hi"
```

Files are text, up to 2 MB.

## Start, stop, and delete

```bash
pxxl sandbox stop demo          # pause: $0, /workspace kept
pxxl sandbox start demo --wait  # resume
pxxl sandbox update demo --auto-stop 0
pxxl sandbox delete demo --yes  # deletes /workspace too
```

`delete` asks first in a terminal. In scripts, pass `--yes`.

## Inspect

| Command | What it shows |
| --- | --- |
| `pxxl sandbox list` | Every sandbox with status, size, price, auto-stop, and preview URL, then what's running and this month's spend. |
| `pxxl sandbox get <sandbox>` | One sandbox in detail. |
| `pxxl sandbox usage <sandbox>` | Billed and not-yet-billed cost, and each run. |
| `pxxl sandbox logs <sandbox>` | Provisioning events and recent output. |
| `pxxl sandbox pricing` | Rates, sizes, templates, and plan limits. Works without signing in. |

## Terminal

```bash
pxxl sandbox terminal demo
```

Opens an interactive shell in the sandbox. Press **Ctrl-]** to disconnect. `--url` prints the one-time WebSocket URL instead, for another client. The terminal is available when terminals are enabled for your account.

## Use a staging Gateway

Set `PXXL_API_URL` to send the CLI to another Pxxl Gateway. Only `https://` hosts under `pxxl.app` and `localhost` are accepted.

```bash
PXXL_API_URL=https://staging-gateway.pxxl.app pxxl sandbox list
```
