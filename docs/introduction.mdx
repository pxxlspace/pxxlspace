Pxxl is a cloud platform for shipping web apps, APIs, databases, and the services around them. You bring the code. Pxxl builds it, runs it, gives it a URL with HTTPS, and keeps it online.

## What you can run

| | |
| --- | --- |
| **Web services** | Node.js, Python, PHP, Go, Rust, Java, .NET, Ruby, Docker. Anything that listens on a port. |
| **Static sites** | Vite, React, Vue, Astro, plain HTML. Served from the edge with no server. |
| **Functions** | Small HTTP handlers next to a frontend, like Vercel functions. |
| **Databases** | Postgres, MySQL, MongoDB, Redis and more. |
| **Your own servers** | Link a Linux server and watch it from the dashboard. |

## How a deploy works

1. You push code, run `pxxl deploy`, or upload a zip.
2. Pxxl detects the stack and builds it in an isolated builder.
3. A web service starts in a container and must pass a health check. A static site is published to the edge.
4. Traffic moves to the new version only when it's healthy. The old one stays up until then.
5. You get a URL. Add your own domain whenever you like.

## Words we use

| Term | Meaning |
| --- | --- |
| **Project** | One app. It has deployments, a URL, variables, logs, and settings. |
| **Deployment** | One build of one commit. You can roll back to any earlier one. |
| **Service** | One process in a project. A monorepo can have several. |
| **Spaceship** | A team. Projects can belong to you or to a spaceship. |
| **Environment** | A set of variables and deployments, such as production or staging. |
