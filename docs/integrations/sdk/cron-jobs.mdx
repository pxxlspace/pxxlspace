## Create a cron job

<ParamField body="name" type="string" required>
  Name shown in Pxxl.
</ParamField>

<ParamField body="schedule" type="string" required>
  Five-field cron expression such as `*/5 * * * *`.
</ParamField>

<ParamField body="url" type="string" required>
  Public HTTP or HTTPS endpoint called by the job.
</ParamField>

<ParamField body="method" type="GET | POST | PUT | PATCH | DELETE">
  HTTP method used for the request. Python sends `GET` unless you pass another method.
</ParamField>

<ParamField body="headers" type="object">
  Request headers sent to the endpoint. Not available in Rust.
</ParamField>

<ParamField body="timeoutSeconds" type="number">
  Maximum time to wait for a response, in seconds.
</ParamField>

<ParamField body="projectId" type="string">
  Project associated with the job.
</ParamField>

<ParamField body="teamId" type="string">
  Team that owns the job.
</ParamField>

<Tabs>
  <Tab title="Node.js">
    ```ts
    const job = await pxxl.cron.create({
      name: "cache warmer",
      schedule: "*/5 * * * *",

      headers: { Authorization: `Bearer ${process.env.JOB_TOKEN}` },
      timeoutSeconds: 30,
    });
    ```

## Cron operations

| Operation | Node.js | Parameters | Returns |
| --- | --- | --- | --- |
| List | `cron.list(input?)` | `teamId?` | `{ cronJobs }` |
| Get | `cron.get(id, teamId?)` | Job ID, `teamId?` | Cron job |
| Create | `cron.create(input)` | Fields above | Cron job |
| Update | `cron.update(id, input)` | Any create field, `status?` | Updated cron job |
| Delete | `cron.delete(id, teamId?)` | Job ID, `teamId?` | Action result |
| Start | `cron.start(id, teamId?)` | Job ID, `teamId?` | Action result |
| Stop | `cron.stop(id, teamId?)` | Job ID, `teamId?` | Action result |
| Trigger | `cron.trigger(id, teamId?)` | Job ID, `teamId?` | Accepted run result |
| Runs | `cron.runs(id, input?)` | `page?`, `limit?`, `teamId?` | `{ runs, total?, page?, limit?, totalPages? }` |
| Validate schedule | `cron.validateSchedule(schedule)` | Cron expression | Validation result |
| Validate URL | `cron.validateURL(url)` | URL | Validation result |

## Trigger and read a run

```ts
const trigger = await pxxl.cron.trigger("cron_123");
const history = await pxxl.cron.runs("cron_123", { page: 1, limit: 20 });
```

  Job headers can contain secrets. Keep cron management in trusted server code.
</Note>

## Other languages

| Operation | Go | Python | Rust |
| --- | --- | --- | --- |

Python sends extra keyword arguments to the API as they are, so use the API's field names: `timeoutSeconds`, `projectId`, and `headers`. Pass the team as `team_id`. In Go and Rust, set the team with the input's `TeamID` or `team_id` field.

## Handle plan limits

Plan and resource-limit responses include structured fields. Use the SDK helper instead of parsing response text or hardcoding plan limits.

<Tabs>
  <Tab title="Node.js">
    ```ts
    import { isPlanGateError } from "@pxxlapp/pxxl";

    try {
      await pxxl.cron.create({
        name: "invoice reconciliation",
        schedule: "*/10 * * * *",
        url: "https://api.example.com/jobs/reconcile-invoices",
        method: "POST",
      });
    } catch (error) {
      if (isPlanGateError(error)) {
        console.log(error.code, error.limit, error.current, error.requiredPlan);
      }
    }
    ```
  </Tab>
  <Tab title="Go">
    ```go
    var apiErr *pxxl.APIError
    if errors.As(err, &apiErr) && apiErr.IsPlanGate() {
      log.Println(apiErr.Code, apiErr.Limit, apiErr.Current, apiErr.RequiredPlan)
    }
    ```
  </Tab>
  <Tab title="Python">
    ```python
    from pxxl import is_plan_gate_error

    if is_plan_gate_error(error):
        print(error.code, error.limit, error.current, error.required_plan)
    ```
  </Tab>
  <Tab title="Rust">
    ```rust
    if error.is_plan_gate() {
        eprintln!("The current plan cannot create another cron job");
    }
    ```
  </Tab>
</Tabs>
