---
title: "CDN and Storage API"
description: "Deliver files globally and manage S3-compatible object storage."
---

Use CDN endpoints for directly served assets. Use Storage endpoints for buckets, objects, access keys, billing, and analytics. Both need a key scoped to `all` or `cdn`, and a paid plan. Storage buckets and access keys need Pro or Enterprise.

## Create a bucket

`POST /storage/buckets`

<ParamField body="name" type="string" required>
  Display name, 3 to 120 characters. Must be unique in your account.
</ParamField>

<ParamField body="visibility" type="private | public" default="private">
  Bucket visibility.
</ParamField>

<ParamField body="region" type="string">
  Preferred region when available.
</ParamField>

<ParamField body="cacheMode" type="string">
  Optional public cache behavior.
</ParamField>

<ParamField body="versioning" type="boolean" default="false">
  Enables supported object versioning.
</ParamField>

```bash
curl --request POST \
  https://server.pxxl.app/api/v3/storage/buckets \
  --header "Authorization: Bearer $PXXL_API_KEY" \
  --header "Idempotency-Key: create-uploads-001" \
  --header "Content-Type: application/json" \
  --data '{"name":"uploads","visibility":"private","versioning":true}'
```

**Response** `201`

```json
{
  "success": true,
  "bucket": {
    "id": "bucket_123",
    "name": "uploads",
    "slug": "uploads",
    "visibility": "private",
    "status": "active",
    "storageBytes": 0,
    "bandwidthBytes": 0,
    "objectCount": 0,
    "createdAt": "2026-08-17T08:00:00Z"
  }
}
```

A duplicate name returns `409`. A plan without Storage returns `403` with `requiredPlan`.

## Objects

Read and write bucket objects by key with these routes. For large files and bulk transfers, use the S3 API with a bucket access key.

| Method | Path | Parameters | Returns |
| --- | --- | --- | --- |
| `GET` | `/storage/buckets/{bucketId}/objects` | `prefix?`, `search?`, `sort?`, `limit?` (1 to 200, default 50), `offset?`, `olderThanDays?` | `{ success, objects, total, prefix, nextOffset? }` |
| `GET` | `/storage/buckets/{bucketId}/objects/stats` | `prefix?` | `{ success, prefix, stats, duplicates }` |
| `GET` | `/storage/buckets/{bucketId}/object` | `key`, `content?` | `{ success, object, content? }` |
| `PUT` | `/storage/buckets/{bucketId}/object` | `{ key, content, contentType? }` | `{ success, replaced, object }` |
| `DELETE` | `/storage/buckets/{bucketId}/object` | `key` | `{ success, deleted }` |
| `POST` | `/storage/buckets/{bucketId}/object/copy` | `{ from, to, overwrite? }` | Copy result |
| `POST` | `/storage/buckets/{bucketId}/object/move` | `{ from, to, overwrite? }` | Move result |
| `POST` | `/storage/buckets/{bucketId}/objects/delete-prefix` | `{ prefix, dryRun? }` | Deleted count, or a preview when `dryRun` is true |

`sort` is `key`, `newest`, `oldest`, `largest`, or `smallest`. With `content=true`, text objects up to 256 KB include their `content`. `PUT` accepts text content up to 1 MB and returns `413` above that.

```bash
curl --request PUT \
  https://server.pxxl.app/api/v3/storage/buckets/bucket_123/object \
  --header "Authorization: Bearer $PXXL_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{"key":"config/settings.json","content":"{\"theme\":\"dark\"}","contentType":"application/json"}'
```

```json
{
  "success": true,
  "replaced": false,
  "object": {
    "key": "config/settings.json",
    "size": 16,
    "contentType": "application/json",
    "etag": "9b2cf535f27731c974343645a3985328",
    "updatedAt": "2026-08-17T08:05:00Z",
    "createdAt": "2026-08-17T08:05:00Z"
  }
}
```

## Upload a file

`POST /cdn/assets`

This endpoint uses `multipart/form-data`. Without `bucketId` the file goes to your CDN space. With `bucketId` it goes into that bucket.

<ParamField body="file" type="file" required>
  File contents.
</ParamField>

<ParamField body="bucketId" type="string">
  Destination bucket ID.
</ParamField>

<ParamField body="path" type="string">
  Object path inside the bucket.
</ParamField>

<ParamField body="visibility" type="private | public" default="public">
  Per-file visibility.
</ParamField>

<ParamField body="kind" type="string" default="file">
  Asset kind.
</ParamField>

<ParamField body="projectId" type="string">
  Project to link the asset to.
</ParamField>

```bash
curl https://server.pxxl.app/api/v3/cdn/assets \
  --header "Authorization: Bearer $PXXL_API_KEY" \
  --form "file=@avatar.png" \
  --form "bucketId=bucket_123" \
  --form "path=avatars/ada.png" \
  --form "visibility=private"
```

**Response** `201`

```json
{
  "success": true,
  "asset": {
    "id": "asset_123",
    "fileName": "avatar.png",
    "key": "storage/bucket_123/avatars/ada.png",
    "contentType": "image/png",
    "size": 48120,
    "publicUrl": "",
    "visibility": "private",
    "kind": "file",
    "storageBucketId": "bucket_123",
    "createdAt": "2026-08-17T08:05:00Z"
  }
}
```

## Create an S3 access key

`POST /storage/buckets/{bucketId}/access-keys`

<ParamField body="name" type="string">
  Label for the integration using the key.
</ParamField>

<ParamField body="permission" type="read | read_write" default="read">
  Allowed S3 operations.
</ParamField>

```bash
curl --request POST \
  https://server.pxxl.app/api/v3/storage/buckets/bucket_123/access-keys \
  --header "Authorization: Bearer $PXXL_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{"name":"media-worker","permission":"read_write"}'
```

**Response** `201`

```json
{
  "success": true,
  "key": {
    "id": "key_123",
    "name": "media-worker",
    "accessKeyId": "pxxl_access_123",
    "secretAccessKey": "shown-only-once",
    "permission": "read_write",
    "status": "active",
    "endpoint": "https://storage.pxxl.app/s3",
    "region": "auto",
    "bucket": "uploads",
    "pathStyle": true,
    "createdAt": "2026-08-17T08:00:00Z"
  },
  "notice": "Save the secret access key now. Pxxl will not show it again."
}
```

<Warning>
  `secretAccessKey` is returned once. Store it securely and never include it in logs.
</Warning>

Use the Pxxl API key only for bucket and key management. Send S3 requests to the returned endpoint with the bucket-scoped `accessKeyId` and `secretAccessKey`. Do not send `PXXL_API_KEY` to `https://storage.pxxl.app/s3`.

| Method | Path | Parameters | Returns |
| --- | --- | --- | --- |
| `GET` | `/storage/buckets/{bucketId}/access-keys` | None | `{ success, keys }` without secrets |
| `GET` | `/storage/buckets/{bucketId}/access-key-names` | None | `{ success, keys, connection }` |
| `POST` | `/storage/buckets/{bucketId}/access-keys` | `name?`, `permission?` | `201` with key and one-time secret |
| `DELETE` | `/storage/buckets/{bucketId}/access-keys/{keyId}` | None | `{ success }` |
