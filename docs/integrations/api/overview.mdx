Use the API when an SDK is unavailable for your language or you need direct control over requests. Every path in these pages is relative to this base URL:

```text
https://server.pxxl.app/api/v3
```

## First request

```bash
curl https://server.pxxl.app/api/v3/cli/whoami \
  --header "Authorization: Bearer $PXXL_API_KEY" \
  --header "Accept: application/json"
```

```json
{
  "success": true,
  "user": { "id": "user_123", "email": "developer@example.com" },
  "authMethod": "api_key",
  "apiKeyId": "key_123",
  "apiKeyScope": "all",
  "apiKeyPermission": "read_write",
  "teamId": ""
}
```

`teamId` is empty for a personal key and holds the team ID for a team-scoped key.

## Request formats

| Content | Format |
| --- | --- |
| Most request bodies | `application/json` |
| Source and asset uploads | `multipart/form-data` |
| Downloads | Binary response body |
| MCP | JSON-RPC 2.0 at the separate MCP endpoint |

```mermaid
flowchart LR
  Client["Your server"] -->|"HTTPS and API key"| Gateway["Pxxl API"]
  Gateway --> Services["Projects and platform services"]
  Services --> Gateway
  Gateway -->|"JSON or binary response"| Client
```

## Plans

API keys work on paid plans. Most modules (projects, deployments, environment variables, domains, cron jobs, CDN, storage, analytics, and usage) return `402` when the key owner has no active paid plan. Databases, teams, servers, and tools accept any valid key, and their own plan limits still apply.

## Rate limits

Each endpoint has its own per-minute limit. Responses include `X-RateLimit-Limit`, `X-RateLimit-Remaining`, and `X-RateLimit-Reset` (seconds until the window resets). Over the limit you get `429`.
