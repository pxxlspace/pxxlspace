---
title: "Functions"
description: "Add HTTP handlers to a static site, Vercel-style."
---

Functions turn files in a folder, such as `api/`, into HTTP endpoints next to your static frontend. Pxxl builds them with your site and serves both as one deployment. Existing Vercel `api/` handlers usually work without changes.

Functions are on paid plans. They run on your project's compute and are not billed per request.

## Turn them on

Functions are off until you enable them in `pxxl.toml`:

```toml pxxl.toml
version = 1

[functions]
enabled = true
root = "api"      # folder with your handlers (default "api")
prefix = "/api"   # URL prefix (default "/api")
```

Commit `pxxl.toml` and your handler files, then deploy. Having an `api/` folder alone does nothing.

## File to URL

Each file in `root` becomes a route under `prefix`:

| File | URL |
| --- | --- |
| `api/index.ts` | `/api` |
| `api/hello.ts` | `/api/hello` |
| `api/users/[id].ts` | `/api/users/123` |

- Extensions: `.js`, `.mjs`, `.cjs`, `.ts`, `.mts`, `.cts`.
- Files and folders starting with `_` (like `api/_lib`), `*.d.ts`, `*.test.*`, and `*.spec.*` are skipped. Use `_lib` for shared code.
- Up to 8 folder levels. Your plan sets the number of routes: 25 on Plus, 50 on Pro, 100 on Enterprise.

## Write a handler

Vercel-style:

```ts api/hello.ts
import type { VercelRequest, VercelResponse } from "@vercel/node";

export default function handler(req: VercelRequest, res: VercelResponse) {
  res.status(200).json({ hello: req.query.name ?? "world" });
}
```

Web-standard:

```ts api/users/[id].ts
export async function GET(request: Request) {
  const id = new URL(request.url).pathname.split("/").pop();
  return Response.json({ id });
}
```

`req` has `query`, `cookies`, and a parsed JSON `body`. `res` has `status()`, `json()`, `send()`, `redirect()`, `setHeader()`, `getHeader()`, `write()`, and `end()`. Named exports like `GET` and `POST` win over the default export.

Read secrets from `process.env`. Set them in [environment variables](/deploy/environment-variables).

## Route a page to a function

A rewrite can send page requests to a function. The browser keeps the original URL.

```toml
[[rewrites]]
source = "/:slug"
destination = "/api/og?username=:slug"
has_header = { key = "user-agent", regex = "(?i).*(twitterbot|whatsapp|discordbot).*" }
```

A rewrite into `/api` must point at a function that exists, or the deploy fails.

## Cache responses

Send `Cache-Control` with `s-maxage` and Pxxl caches the response (up to 1 hour):

```ts
res.setHeader("Cache-Control", "public, s-maxage=300");
```

Private responses, `no-store`, responses that set cookies, errors, and bodies over 1 MiB aren't cached. A new deploy starts with an empty cache.

## Limits

| | Plus | Pro | Enterprise |
| --- | --- | --- | --- |
| Routes | 25 | 50 | 100 |
| Timeout | 10 s | 30 s | 60 s |
| Concurrent requests | 10 | 50 | 200 |
| Requests per minute | 300 | 1,500 | 6,000 |

Request bodies are limited to 4 MiB by default. Set lower limits, or per-route limits, in [`[functions]`](/reference/pxxl-toml#functions).

## When the deploy fails

| Error | Meaning |
| --- | --- |
| `FUNCTIONS_NO_HANDLERS` | `root` has no handler files. |
| `FUNCTIONS_SERVER_CONFLICT` | The project is a server app (Express, Next.js, Dockerfile, multiple services...). Functions are for static sites. |
| `FUNCTIONS_TYPE_LOCKED` | The project was already deployed as a web service. |
| `FUNCTIONS_PLAN_REQUIRED` | Functions need a paid plan. |
| `FUNCTION_REWRITE_TARGET_MISSING` | A rewrite points at a function that doesn't exist. |

Your current deployment stays live. Errors inside a handler go to **Live Logs**; callers get a generic error. The **Functions** tab lists your routes and their limits.

## Coming from Vercel

Keep your `api/` folder and handlers. Add the `[functions]` block above. Move routing from `vercel.json` to `pxxl.toml`, or keep `vercel.json` for routing only. See [Migrate from Vercel](/migrate/vercel).
