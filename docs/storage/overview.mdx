| Use | For |
| --- | --- |
| **Storage buckets** | User uploads, private files, backups. S3-compatible, with access keys. |
| **CDN** | Public files you want served fast: images, fonts, downloads. |

## Create a bucket

Open **Storage** in the sidebar and create a bucket. Buckets are **private** by default. Make one **public** if its files should open without signing in.

```bash
pxxl storage create uploads
pxxl storage object-upload <bucket-id> ./logo.png --path brand/logo.png --public
```

## Use any S3 tool

Create an access key for the bucket. A key works for one bucket only and is either read-only or read-write. The secret is shown once.

```bash
pxxl storage key-create <bucket-id> --name app
```

Then point any S3 client at the endpoint the key page shows:

```js
import { S3Client, PutObjectCommand } from "@aws-sdk/client-s3";

const s3 = new S3Client({
  endpoint: process.env.PXXL_S3_ENDPOINT,
  region: "auto",
  credentials: {
    accessKeyId: process.env.PXXL_S3_ACCESS_KEY_ID,
    secretAccessKey: process.env.PXXL_S3_SECRET_ACCESS_KEY,
  },
});

await s3.send(new PutObjectCommand({
  Bucket: process.env.PXXL_S3_BUCKET,
  Key: "invoices/inv_123.pdf",
  Body: pdfBytes,
}));
```

The Pxxl SDK has a built-in client with signed URLs. See [SDK: CDN and storage](/integrations/sdk/cdn-storage).

Never send your Pxxl API key to the S3 endpoint. Use the bucket key.

## CDN

```bash
pxxl cdn upload ./hero.jpg
pxxl cdn list
```

Uploaded files get a public URL you can use in your site. Add `--private` to keep a file private.

## Bring your own bucket

Some features write to a bucket you own instead: [log drains](/projects/log-drains) and [database backups](/databases/backups). They accept any S3-compatible provider (AWS S3, Cloudflare R2, MinIO) on a public HTTPS endpoint.
