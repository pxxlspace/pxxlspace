Pxxl reads the files in a repository before it builds. It uses them to choose the language, package manager, framework, build commands, and deployment target.

Detection gives you a starting point. You can review and change the build settings before deployment.

## <img src="https://cdn.simpleicons.org/nodedotjs" alt="" width="20" height="20" style={{display:"inline-block",verticalAlign:"middle",marginRight:"6px"}} /> Node.js and TypeScript

Pxxl detects Node.js projects from <code>package.json</code>. It supports npm, pnpm, Yarn, and Bun.

The lockfile chooses the package manager:

- <code>pnpm-lock.yaml</code> uses pnpm.
- <code>yarn.lock</code> uses Yarn.
- <code>bun.lock</code> or <code>bun.lockb</code> uses Bun.
- Without one of these files, Pxxl uses npm.

## <img src="https://cdn.simpleicons.org/docker" alt="" width="20" height="20" style={{display:"inline-block",verticalAlign:"middle",marginRight:"6px"}} /> Docker

Docker deployments use a <code>Dockerfile</code> or a Docker image directly. Pxxl skips framework detection and runs the result as a Web Service.

## When detection needs help

Open **Build Configuration** in the Deploy flow and check:

- the base directory
- the language and framework
- the package manager
- the install command
- the build command
- the start command
- the port

For repeatable settings, add a <code>pxxl.toml</code> file to the project. Pxxl reads it when it creates the build plan and still lets you review the result before deployment.
